# 技术内容深度分析技能

读取 `knowledge/raw/` 中的原始采集数据，逐条进行深度分析（摘要、技术亮点、评分、标签），并发现整体趋势，输出结构化分析结果。

## 使用场景

- 需要对采集的原始数据进行结构化分析
- 需要为每条内容打分排序以确定优先级
- 需要识别当前批次的共同主题和新兴概念
- 为下游 Organizer 提供标签和评分数据

## 执行步骤

### Step 1：读取最新采集文件

从 `knowledge/raw/` 中找到最新的 JSON 采集文件（按文件名排序取最后一个），读取全部条目。

### Step 2：逐条深度分析

对每条内容执行以下分析：

**摘要**（50 字以内，中文）
- 公式：`项目名（标题） + 核心功能 + 一句话说明为什么值得关注`

**技术亮点**（2-3 条，用事实说话）
- 每条亮点必须包含可验证的客观事实：Star 数、性能指标、支持的模型数量、相比竞品的优势等
- 格式：`亮点描述（依据）`
- ✅ 示例：`支持 3000+ 站点查询（同类工具最多）`
- ❌ 示例：`功能非常强大` — 空洞，缺少依据

**评分**（1-10 分整数，附理由）

| 分值 | 含义 | 说明 |
|------|------|------|
| 9-10 | ⭐ 改变格局 | 突破性研究或重磅发布，可能影响行业方向 |
| 7-8 | ✅ 直接有帮助 | 实用的工具/框架/教程，可立即用在实际项目中 |
| 5-6 | 📖 值得了解 | 有参考价值的信息，拓宽视野但不紧急 |
| 1-4 | ⏭ 可略过 | 营销内容、重复信息或与 AI/LLM/Agent 关系不大 |

**标签建议**（2-5 个）
- 从内容的核心技术、应用领域、工具类型三个维度选取
- 中文标签为主，通用术语可用英文（如 `LLM`、`RAG`、`Agent`）

### Step 3：趋势发现

完成逐条分析后，对整个批次做全局观察：

- **共同主题** — 这批项目集中在哪些领域？（如"多 Agent 协作"、"本地化部署"）
- **新概念** — 是否有之前没出现过的新技术、新框架、新思路？
- **热度分布** — 高分段（7-10）和低分段（1-4）各占多少比例？

### Step 4：输出分析结果 JSON

将全部结果写入 `knowledge/analyzed/tech-summary-YYYY-MM-DD.json`。

## 约束规则

1. **评分分布** — 一批 15 个项目中，评 9-10 分的**不超过 2 个**。评分应具有区分度，避免打分膨胀
2. **分数对齐** — 所有评分必须与评分标准的文字定义一致：给 9 分一定是"改变格局"级别，而非"还不错"
3. **不编造** — 技术亮点中的依据必须是原文或公开可查的事实，禁止虚构数据
4. **中文优先** — 摘要、亮点、评分理由、趋势描述均为中文；标签可中英混用

## 注意事项

1. **输入判空** — 若 `knowledge/raw/` 不存在或为空，直接终止并报告原因
2. **字段完整性** — 输出 JSON 中的每条必须包含所有字段，不允许缺省
3. **趋势非空话** — 趋势发现中的共同主题和新概念必须具体可验证，避免"AI 发展迅速"之类空泛表述
4. **溯源性** — 确保 Analyzer 与 Organizer 之间的数据通过 `knowledge/analyzed/` 中间层衔接，而非口头传递
